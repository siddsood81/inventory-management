Filter Data Flow — End to End

1

User selects a filter

FilterBar.vue updates selectedLocation.value = 'London' in the singleton useFilters() composable — no prop drilling needed.

2

Reactive watch fires in the view

Each view watch()es the filter refs. A change triggers loadData(), which calls getCurrentFilters() to get a clean params object.

3

api.js builds the HTTP request

Filter values are appended to URLSearchParams. Values equal to 'all' are skipped. Axios fires GET /api/orders?warehouse=London.

4

FastAPI filters in-memory data

apply_filters(orders, warehouse='London') iterates the in-memory list. For time filters, filter_by_month() handles both 2025-06 and Q2-2025 formats.

5

Response → Vue computed properties

Raw results stored in a ref(). Derived data (status counts, totals) live in computed() properties and re-evaluate automatically. The table re-renders.

Key Architectural Patterns

Singleton Composable for Filters

useFilters() creates its refs at module scope, not inside the function. Every component that calls it shares the same state — no Vuex/Pinia required. The reset button in FilterBar.vue automatically affects all views.

Raw Refs + Computed Derived Data

Each view stores raw API results in a ref(). Status breakdowns, totals, and sort orders live in computed() properties so they re-evaluate only when dependencies change — no manual re-filtering on every render.

Stateless Backend — JSON Loaded Once

All JSON files are loaded into Python dicts at process startup via mock_data.py. Endpoints filter copies of this data; the originals are never mutated. A server restart reloads everything from disk.

Bilingual UI (EN / JA)

useI18n() switches all labels, product names, warehouse names, and currency (USD ↔ JPY) based on a locale stored in localStorage. No page reload required.
